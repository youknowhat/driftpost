# 둥실둥실

접은 종이배에 편지를 실어 바다에 띄우고, 낯선 누군가가 그걸 주워 답장을 보내는 웹.
편지는 **두 항구 사이를 실제 배의 속도(20노트 · 시속 37km)로** 건너간다. 그래서 서울에서
도쿄까지 하루 반, 서울에서 뉴욕까지 열이틀이 걸린다. 그 기다림이 이 서비스의 본체다.

- `index.html` — 앱 전체 (단일 파일: 픽셀 캔버스 렌더러, Web Audio 파도 소리, 세계지도, Supabase 클라이언트)
- 백엔드 — Supabase (테이블 `dp_*`, 마이그레이션은 상위 저장소 `supabase/migrations/00{2,3,4,5}_driftpost*.sql`)

## 규칙

| | |
|---|---|
| 편지 길이 | 500자 |
| 배 속도 | 20노트 (37.04 km/h) |
| 최소 표류 | 20분 |
| 배 수명 | 30일 (등대지기 배는 예외) |
| 동시 슬롯 | 띄운 배 1척 · 주운 배 1척 |
| 줍기 제한 | 시간당 20통 |
| 발견 조건 | `표류 시간 × 속도 ≥ 두 항구 사이 거리` |

## 이어가기 (로그인 없이 기기 옮기기)

신원은 `dp_link(uid → sailor_id)` 로 브라우저에서 분리돼 있다. 가입할 때 단어 넷짜리
**이어가기 열쇠**(예: `물결-접기-그물-썰물`)를 만들어 브라우저에 두고, 서버에는 `sha256` 만 남긴다.
다른 기기에서 그 열쇠를 넣거나 `#k=<열쇠>` 링크를 열면 같은 사람으로 이어진다.

- 열쇠 평문은 서버에 없다. 잃어버리면 복구할 수 없다.
- 대입 시도는 계정당 시간 10회로 제한된다 (`dp_claim_try`).
- 진행 중인 편지가 있는 브라우저는 다른 열쇠로 덮어쓰지 않는다 (`device busy`).
- 며칠 뒤 도착을 기억할 방법이 없어서, 항해 화면에서 도착 시각을 `.ics` 로 내려받을 수 있다.

## 설계상 중요한 것

- **도착 전 본문은 서버가 내려주지 않는다.** RLS 정책(`dp_letter_read`)이 `arrives_at <= now()`
  를 강제하므로, 클라이언트를 어떻게 만져도 기다림을 건너뛸 수 없다.
- **로그인이 없다.** Supabase 익명 인증으로 브라우저에 열쇠 하나만 남는다.
- **위치는 0.25도(약 25km) 격자로 반올림**해서 저장하고, 화면에는 가장 가까운 바다 이름만 쓴다.
  편지를 주고받는 상대에게는 지도용으로 **1도(약 111km)** 까지 더 뭉갠 좌표만 나간다.
- **모든 쓰기는 `SECURITY DEFINER` RPC를 통해서만** 일어난다. 테이블 직접 쓰기 정책은 없다.
- **접은 편지는 되돌아가지 않는다.** 한쪽이 접으면 `dp_release` 는 배를 되살리지 않고
  상대 슬롯만 비운다 — 접은 사람의 기록을 지우거나, 끝난 편지를 새 사람에게 다시 보내지 않는다.
- **오래된 병편지**는 바다가 비어 있을 때를 위한 장치이고, 화면에서 사람이 아님을 명시한다.
  사람이 띄운 배가 언제나 먼저 발견된다.
